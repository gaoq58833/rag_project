# 容器镜像与镜像仓库

## 镜像分层与构建

镜像由多层只读文件系统叠加而成，每条 Dockerfile 指令生成一层。把不常变化的依赖安装放在前面，把频繁变化的业务代码放在后面，可以最大化复用缓存，缩短构建时间。合并 RUN 指令、清理包管理缓存，能减小镜像体积。

多阶段构建把编译环境和运行环境分开：第一阶段安装编译工具和依赖并产出二进制，第二阶段只拷贝产物到精简基础镜像。这样最终镜像不含编译器和源码，体积更小、攻击面更少。基础镜像要固定到具体版本或摘要，避免 latest 漂移导致构建结果不可复现。

## 镜像仓库与分发

镜像仓库分公有和私有。私有仓库要开启认证和细粒度权限，按项目划分命名空间；跨集群分发时配置地域复制，让节点从就近仓库拉取。镜像标签不要只用 latest，应使用语义化版本或提交哈希，并配合镜像摘要保证可追溯。

拉取凭证通过 Secret 挂载给节点，不要写进镜像或代码仓库。对不可信网络启用 TLS 和镜像签名校验，防止镜像被替换。定期清理无用标签和悬空镜像，控制存储成本。

## 镜像安全与扫描

镜像扫描要覆盖基础镜像的系统包和应用依赖，发现高危漏洞时阻断发布。扫描应在 CI 阶段执行，并把结果作为合并门禁；运行期也要定期重扫，因为漏洞库会更新。

运行容器时使用非 root 用户、只读根文件系统、去掉多余的能力，缩小被攻破后的影响范围。不要在镜像里放密钥和配置文件，改为运行时挂载或注入。
