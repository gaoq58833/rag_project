# 对象存储与 CDN 加速

## 对象存储的使用方式

对象存储以桶为单位组织数据，对象由 key 唯一标识，适合存图片、视频、备份和静态资源。上传大文件要用分片上传：先初始化上传任务，把文件切成固定大小的分片并发上传，最后合并；分片大小要大于最小限制，分片过多会增加请求次数和合并开销。中断后可以按已上传分片续传，不必从头开始。

对象存储通常提供多级存储类型：标准、低频、归档。访问频率低但需要快速取回的数据放低频，长期归档放归档类型，取回需要解冻并产生额外费用。生命周期规则可以按前缀自动转储和删除，避免手工清理遗漏。

## 访问控制与安全

桶的访问权限默认应为私有，通过签名 URL 临时授权下载，URL 设置较短的有效期。不要把 AccessKey 写进前端代码；前端直传时由后端签发临时凭证，限定可写的路径前缀和有效期。

跨域配置要精确到需要的域名和方法，通配符会让任意站点都能读取资源。开启服务端加密和访问日志，对敏感数据使用独立的桶和密钥，便于审计和隔离。

## CDN 缓存与回源

CDN 把静态资源缓存到离用户近的节点，降低源站压力和访问延迟。缓存键要包含影响内容的参数，例如语言、清晰度；把无关的跟踪参数排除，避免同一资源产生大量缓存副本。缓存时间按资源是否可变设置：带内容哈希的文件名可以长期缓存，配置文件和接口响应要短缓存或协商缓存。

刷新和预热是发布流程的一部分：发布新版本后主动刷新变更的 URL，或使用新文件名实现自然失效。回源带宽要有限制，源站要能承受缓存穿透时的回源洪峰，必要时开启回源收敛，让同一资源的并发回源合并为一次。
