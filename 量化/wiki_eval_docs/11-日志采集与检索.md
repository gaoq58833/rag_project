# 日志采集与检索体系

## 采集与传输

应用日志先写本地文件或标准输出，由采集 agent 读取并发送到消息队列。容器环境下推荐把日志打到标准输出，由节点级 agent 统一收集，避免在容器内维护文件轮转。agent 要支持多行日志合并，否则 Java 异常栈会被拆成一行行孤立记录，检索时无法还原上下文。

传输链路要能承受后端抖动：队列起到缓冲作用，agent 在发送失败时本地暂存并重试，磁盘缓冲要设上限和过期时间，防止把节点磁盘写满。日志中不要打印密码、令牌、完整身份证号，脱敏应在采集阶段完成，而不是等到检索时。

## 索引与存储

日志检索通常基于倒排索引。为控制索引体积，只对需要检索的字段建索引，其余字段作为原始内容存储。时间字段用日期分层管理，按天或按小时滚动索引，便于按时间范围裁剪查询。分片数要按数据量和节点数规划，分片过多会增加集群元数据压力，过少则无法并行。

历史日志按生命周期策略自动迁移：热数据保留在高速存储，超过一定天数转到低成本存储或直接删除。保留期要满足审计和排障要求，常见为 7 到 30 天，核心系统的审计日志单独长期保存。

## 检索与成本控制

查询时尽量带上时间范围和服务名过滤，避免全量扫描；模糊匹配和正则查询代价高，应限制使用频率。对高频查询可以建立固定报表或快照，减少重复扫描。

成本主要来自存储和写入。降低成本的措施包括：关闭不必要的字段索引、压缩原始日志、对调试级别日志做采样或按需开启、在入口做日志量配额。日志量突然上涨往往意味着异常循环或重复打印，应配置日志量突增告警。
