# 单点登录与 OAuth2

## 单点登录的基本流程

单点登录让用户在一个系统登录后访问其他系统无需重复输入密码。典型流程：用户访问业务系统，未登录时跳转到统一认证中心；认证中心完成登录后生成票据，重定向回业务系统并附带一次性 code；业务系统用 code 向认证中心换取用户身份，建立本地会话。code 只能使用一次且有效期很短，防止被截获后重放。

退出登录要同时清理认证中心和各业务系统的会话。常见做法是认证中心维护会话与业务系统的登记关系，退出时通知各系统清理；如果没有统一退出，用户在一个系统退出后其他系统仍保持登录，存在安全风险。

## OAuth2 授权模式

OAuth2 解决的是「第三方应用在用户授权下访问资源」，不是身份认证本身。授权码模式最常用：前端跳转授权页，用户同意后拿到 code，后端用 code 换 access token，refresh token 用于续期。隐式模式已不推荐，因为 token 直接暴露在前端。

客户端凭证模式用于服务间调用，没有用户参与；密码模式要求应用直接接触用户密码，只适合高度信任的第一方应用。选择模式要看是否有用户授权、客户端能否安全保存密钥。

## Token 管理与安全

access token 有效期要短，泄露后的影响窗口小；refresh token 有效期长但要能撤销，并绑定客户端。token 要校验签名、过期时间、签发方和受众，不能只解码不验签。

防止授权码拦截要使用 PKCE，尤其是在无法安全保存密钥的公共客户端。回调地址必须白名单精确匹配，防止开放重定向把 code 送到攻击者服务器。敏感操作应要求二次认证，而不是仅凭长期有效的 token。
