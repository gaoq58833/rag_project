# 缓存穿透、击穿与雪崩的应对

## 缓存穿透

缓存穿透指查询的 key 在缓存和数据库里都不存在，请求每次都落到数据库。攻击者用大量随机 key 压测时，数据库会被打成瓶颈。两类常用防护：一是对确认不存在的查询缓存空值，并设置较短的过期时间（如 60 秒），避免脏数据长期驻留；二是在缓存前加布隆过滤器，把所有可能存在的 key 预先写入位图，查询先过过滤器，判定不存在就直接返回。

布隆过滤器有假阳性、没有假阴性，删除元素困难。需要删除语义时可以改用计数布隆过滤器或定期重建位图。无论哪种方案，都要给过滤器设置容量上限和误判率，容量估算偏小会导致误判率快速上升。

## 缓存击穿

缓存击穿指某个热点 key 过期的瞬间，大量并发请求同时回源数据库。处理思路是让同一 key 只有一个请求去重建缓存：可以用分布式锁或本地互斥量，未抢到锁的请求短暂等待后重试读缓存；也可以对热点数据采用逻辑过期，即 value 里存过期时间，物理上不设 TTL，读到逻辑过期时异步重建，先返回旧值。

逻辑过期牺牲了短暂的一致性，换来请求不被阻塞，适合商品详情、榜单这类能容忍秒级旧值的场景。互斥重建则保证读到的都是新值，但等待期间接口延迟会升高，需要设置合理的等待上限和降级返回值。

## 缓存雪崩

缓存雪崩指大批 key 在同一时间集中过期，或缓存节点整体不可用，导致流量瞬间全部压到数据库。针对集中过期，可以在基础 TTL 上叠加随机抖动，把过期时间打散到几分钟的区间内；针对节点故障，需要做缓存高可用（主从加哨兵或集群模式），并在应用侧加限流和熔断，避免数据库被瞬时流量击垮。

雪崩的兜底还包括：多级缓存（本地缓存承接热点）、数据库连接池上限保护、以及预热机制。上线或重启后缓存为空，应通过预热任务提前加载热点 key，而不是等真实流量把缓存填满。
